🏠 Обзор проекта

📋 Что такое «Минутка»?

«Минутка» — AI-партнёр для сотрудников в рамках корпоративной программы обучения AI от команды «Алгоритм». В течение двухнедельного цикла сотрудник общается с Минуткой через Telegram: планирует день утром, при желании сверяется днём, рефлексирует вечером — и получает персонализированную обратную связь о паттернах работы, энергии и фокусе.

B2B Telegram Bot AI Agent Mastra Framework TypeScript Privacy-First

👤 Для сотрудника

  • Заботливый AI-дневник рабочего дня
  • Утреннее планирование и вечерний разбор
  • Обнаружение паттернов: рутина, стресс, энергия
  • Персональный отчёт за 2 недели
  • Выбор персоны общения: «Поддержка» или «Эффективность»
  • Полный контроль над своими данными

🏢 Для компании

  • Обезличенная карта автоматизации
  • Топ повторяющихся задач — кандидаты на автоматизацию
  • Распределение времени по категориям
  • Сигналы стресса и нагрузки (агрегированно)
  • Рекомендации: 30 / 60 / 90 дней
  • Без доступа к личным данным и диалогам

⚙️ Бизнес-процессы агента (Agent Manual)

📖 Концепция Agent Manual

Поведение MinutkaAgent управляется не одним гигантским system prompt, а набором атомарных бизнес-процессов в Markdown под git. Каждый процесс — procedural playbook с чёткими секциями: когда применяется, входы, шаги, выходы, privacy-ноты и anti-patterns.

Маршрутизация: SO-CoT Constrained Decision Router выбирает процессы по смыслу, а не по ключевым словам.

Когда: Первый ответ после завершения профиля и принятия consent.

Что делает: Подтверждает получение профиля, объясняет роль Минутки, приглашает к первому действию. Применяет выбранную персону.

Anti-patterns: длинные курсы по AI, давление на участие, оценка продуктивности.

readonlyPhase 3.5

Когда: Вопросы о приватности, данных компании, методологе, удалении данных.

Что делает: Отвечает на вопросы о видимости данных. Отделён от guardrails и insight extraction.

Anti-patterns: смешивание privacy-ответа с рабочей рефлексией.

readonlyPhase 3.5

Когда: Разбор дня: итоги, блокеры, встречи/звонки, усталость, сравнение с утренним планом.

Что делает: Ищет утренний план в контексте. Отражает факты без оценки. Называет 1–2 паттерна: перегруз звонками, context switching, blocked progress. Предлагает один шаг на завтра.

Anti-patterns: «Ты не выполнил план», «Твоя продуктивность низкая», лекции по тайм-менеджменту.

readonlyPhase 3.5

Когда: Запрос на написание контента, ресерч, обучение AI, нерелевантная тема или попытка обхода ограничений.

Что делает: Мягко отказывает и возвращает к рабочей тематике. Основной агент не вызывается.

Anti-patterns: жёсткий отказ, копирование правил из system prompt, скрытое разрешение нерелевантного запроса.

readonlyPhase 3.5

Когда: Decision router отмечает сообщение как insight candidate после substantive workday reflection.

Что делает: Извлекает структурированные сигналы: категории задач, рутина, энергия/стресс, automation candidates. Сохраняет privacy-safe insights.

Мутации: ⚡ persists structured insights

mutatingPhase 3.5

Когда: Сотрудник оценивает ответ: 👍/👌/👎.

Что делает: Обрабатывает оценку предыдущего ответа, не текущий рабочий контент.

Будущее: Запись feedback для дообучения модели.

🧪 Принцип: Specs без внешних API

Все executable specs работают через mock runners и tools — без реального LLM, Telegram API или STT. Это обеспечивает детерминированные, быстрые и надёжные тесты.

🔒 Приватность и границы

🛡 Ключевые принципы

  • Диалог сотрудника = личный контекст, не доступен компании
  • Компания получает только обезличенные агрегаты
  • Минимальная группа для аналитики: ≥5 сотрудников
  • ФИО и телефон маскируются до отправки в AI-провайдеры
  • Методолог НЕ видит транскрипты, задачи и эмоции отдельных людей
  • Сотрудник может удалить все свои данные одним действием
  • Raw transcripts не сохраняются в insights
  • Privacy-safe employeeId (псевдоним, не PII)

🟢 Что видит сотрудник

  • Свой полный диалог с Минуткой
  • Свой портрет и профиль (раздел «Я»)
  • Персональные недельные и финальные отчёты
  • Выбранная персона и настройки
  • Кнопка удаления всех данных

🔴 Что НЕ видят компания и методолог

  • ❌ Транскрипты голосовых сообщений
  • ❌ Конкретные задачи отдельных людей
  • ❌ Эмоциональное состояние конкретного сотрудника
  • ❌ Имена в ответах и рефлексиях
  • ❌ Срезы меньше 5 человек

🔧 Инженерные правила проекта

  • Не ломать слои: Telegram handler не бизнес-слой
  • Specs без внешних API: LLM/Telegram мокируются
  • Mastra docs-first: сверяться с embedded docs перед API
  • Provider registry first: проверять модель перед использованием
  • Privacy by structure: сначала domain types, потом отчёты
  • Business processes as code: process-файлы в git
  • Минимальные коммиты по фазам: зелёный verify → тег
  • Unix-like namespace как контракт агента
