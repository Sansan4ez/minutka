# Персональный AI-ассистент

Персональный AI-ассистент руководителя (Telegram-first, single-owner). Рабочий **прототип** с осознанной ставкой на лёгкую, простую и потому надёжную архитектуру.

Это не чат-бот с универсальными ответами, а управляемая система навыков, настроенная под конкретного человека: его цели, приоритеты, рабочие процессы и контекст. Ассистент собирает и структурирует контекст, помогает планировать день и проекты, сохраняет идеи и готовит материалы — постепенно становясь цифровым «вторым пилотом».

Построен на [Mastra](https://mastra.ai) + TypeScript, переиспользует фундамент проекта «Минутка».

## Архитектура в двух словах

Поток: `Telegram / HTTP / CLI → AssistantService → typed use-cases → stores`.

Агент сам роутит по процессам в один ход (agent-led routing), но **не пишет в хранилища напрямую и не выполняет внешних действий без подтверждения** — всё идёт через типизированные use-cases. База знаний хранится файлами (Markdown) в S3/MinIO, без эмбеддингов и векторной БД: файловая навигация проще, прозрачнее в трейсах и дешевле.

Подробнее — в [`AGENTS.md`](AGENTS.md), целевая архитектура — в [`docs/architecture/`](docs/architecture) ([RFC архитектуры](docs/architecture/rfc-personal-assistant-architecture.md), [agent-led routing](docs/architecture/rfc-agent-led-routing.md)).

## Privacy by Design

Приватность — свойство конструкции хранилища, а не настройка, которую можно забыть включить. Это особенно важно, потому что ассистент — это LLM, и заинжектить её может даже содержимое самого хранилища.

- **Ассистент не видит «сырое» хранилище.** Он работает только с логическими путями (`/proc/context/...`) — без доступа к физическим ключам объектов, именам бакетов, учётным данным и signed URL. Их нет в выходных типах инструментов, поэтому им нечего утечь.
- **Изоляция по владельцу — структурная.** Каждый документ жёстко привязан к владельцу схемой ключей хранилища, а идентификатор владельца задаётся приложением и никогда не принимается из аргументов инструмента. Выйти за пределы своего пространства нельзя в принципе, а не «если правильно настроен фильтр».
- **Журнал без содержимого.** В аудит попадают только факты операций (тип, число результатов, признак усечения, исход) — никогда текст документов или запросов. Наблюдаемость не превращается в теневую копию персональных данных.
- **Надёжная запись.** Изменения атомарны и версионируемы: параллельные операции не затирают друг друга и не теряются.

## Команды

```bash
npm run typecheck      # tsc --noEmit
npm run specs          # executable specs (без сети)
npm run verify         # typecheck + specs
npm run db:migrate     # применить миграции
npm run telegram:dev   # локальный Telegram-бот (polling)
```

## Структура

- [`src/`](src) — код по слоям: `domain/`, `contracts/`, `application/`, `mastra/`, `infrastructure/`, транспорты (`server/`, `telegram/`, `client/`).
- [`vault/`](vault) — Agent Vault: роль ассистента, навыки-процессы, типизированные действия, база знаний пользователя.
- [`docs/`](docs) — архитектура, конвенции, планы, продуктовый бриф, runbooks.
- [`specs/`](specs) — executable specs, гоняются без LLM/сети через in-memory адаптеры.
- [`migrations/`](migrations) — SQL-миграции PostgreSQL.

## Статус

Прототип для пилота / проверки спроса. Отслеживание задач — через [beads](https://github.com/Dicklesworthstone/beads_rust) (`br`) в [`.beads/`](.beads); планы ведутся эпиками, см. [`docs/plans/README.md`](docs/plans/README.md).
