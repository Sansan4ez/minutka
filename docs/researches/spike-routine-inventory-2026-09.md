## Спайк 1. Извлечение `routineLabel` и `recurrence`

### Метод

Офлайн-прогон использовал production-модель из traces (`openai/nath/gpt-5.6-terra`) и текущий prompt extractor-а с anchor `minutka-activity-transaction/v1`, дополненный только правилами §2.3 [RFC инвентаря рутин](../architecture/rfc-routine-inventory-and-quick-wins.md). Для 54 сообщений взят сохранённый bounded context контура `activity_transaction`; для остальных доступных source messages prompt восстановлен тем же production builder-ом. Скрипт читал только экспорт и ничего не писал в PostgreSQL/MinIO.

В activities встречается 151 distinct `sourceMessageId`: payload доступен для 149 сообщений, а 7 из 386 activities ссылаются на два отсутствующих в экспорте сообщения. Успешно обработаны все 149 доступных сообщений. Извлечённые элементы сопоставлены с сохранёнными activities по source message и уже сохранённым closed facets; поэтому метрики ниже считаются по всем 386 activities, а недоступные или несопоставленные элементы учитываются как omit, то есть оценка coverage консервативна.

Ручная проверка PII выполнена методологом по полному набору извлечённых labels в операторском контуре; в репозиторий labels не копируются.

Единственное значение `recurrence`, предложенное моделью, не имело явной частотной формулировки в исходном сообщении и при ручной проверке признано ложноположительным. Для следующих спайков оно трактуется как omit: подтверждённых значений `recurrence` — 0.

Сравнение с существующими facets использовалось как контроль сопоставления, а не как gold-разметка: текущий prompt с новыми полями совпал с сохранённым значением в 326 из 765 сравнений по заполненным stored facets (42,6 %). Это подтверждает, что один повторный LLM-прогон нельзя считать побитовой реконструкцией прежней транзакции; выводы спайка ограничены новыми полями и ручным PII-review.

### Вывод и falsifier

Assumption §2.3 для `routineLabel` **подтверждён на этом корпусе**: coverage 74,6 % выше порога 50 %, PII-rate 0 % ниже порога 5 %, ограничение ≤80 символов выдержано. Falsifier спайка не сработал; правка правила `routineLabel` не требуется.

Assumption о доступности `recurrence` из текущего вечернего самоотчёта **не подтверждён**: сотрудники ни разу явно не назвали частоту, а единственный model output оказался неподкреплённым. Это не falsifier самого правила §2.3 — правило корректно требует omit, — но подтверждает необходимость фразы приглашения §2.10 про длительность и частоту. Длительность самостоятельно названа только в 8,7 % сообщений, поэтому та же фраза нужна и для снижения `unsizedObservations`.

Набор из 386 строк (`activityId`, `subjectKey`, `routineLabel`, скорректированный `recurrence`, facets) сохранён вне репозитория в операторском контуре как вход спайков 2 и 3.
