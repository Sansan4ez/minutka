# Мягкие напоминания и эскалация участия

Оператор сопровождает участие по закрытому participation set выбранной компании и учебной группы. Источник адресатов — `admin list-participants --company <company_id> --group <group_id>` и метка `lagging` или `dropped_off`; содержание разговоров, activities, traces, insights и персональные выводы для отбора не читаются.

## Текущий статус runtime

Scoped-метки участия работают. Групповой Telegram-команды для отправки напоминаний в текущем runtime пока нет. До появления typed operator CLI запрещено имитировать рассылку прямым SQL, изменением личных расписаний, вызовом Telegram Bot API в обход application layer или циклом по transport identifiers.

Если сотрудник требует ручного касания сейчас, оператор переходит ко второму ярусу и связывается с ним вне бота по согласованному каналу. Этот runbook фиксирует обязательный контракт будущей operator-команды; он не объявляет отсутствующую рассылку доступной.

## Формулировка по умолчанию

```text
Здравствуйте! Мягко напоминаю о «Минутке»: если сегодня удобно, просто напишите пару слов о последнем рабочем дне — без оценки и обязательной формы. Если касаний не будет, с вами может связаться методолог программы; при длительном отсутствии методолог может сообщить руководителю компании только факт участия или отсутствия участия, без содержания переписки.
```

Оператор может задать свой текст длиной от 1 до 1000 символов. Текст не должен содержать давление, стыд, сравнение с другими участниками, оценку продуктивности или предположение о причинах отсутствия. Модель текст не генерирует.

## Preview и подтверждение рассылки

Когда typed operator-команда будет подключена, одна операция принимает только:

- точные `company_id` и `group_id`;
- одну метку участия: `lagging` или `dropped_off`;
- явный текст либо формулировку по умолчанию.

Перед внешним действием команда обязана показать:

1. точный company/group scope и выбранную метку;
2. полный текст сообщения без сокращения;
3. число найденных адресатов;
4. число адресатов, исключённых суточным cooldown или отсутствующей Telegram delivery session.

После preview оператор подтверждает отправку отдельным level-2 TTY challenge, содержащим company/group scope, метку и число eligible-адресатов. Ответ `yes`, флаг `--force` или подтверждение через модель не заменяют точное transport-подтверждение. Изменение scope, текста, метки или числа eligible-адресатов инвалидирует preview и требует нового подтверждения.

После попытки команда показывает исход по каждому `employeeId`, не раскрывая transport identifiers и содержание переписки:

- `delivered`;
- `cooldown` — предыдущее напоминание было менее 24 часов назад;
- `delivery_session_missing`;
- `failed` с безопасным кодом причины без provider payload.

## Суточный cooldown

Одному участнику можно отправить не более одного операторского напоминания за скользящие 24 часа независимо от метки, повторного запуска команды и изменений текста. Cooldown проверяется до подтверждения и повторно непосредственно перед доставкой. Получатель со статусом `cooldown` не включается в число eligible-адресатов; обхода `--force` на пилоте нет.

Личное утреннее или вечернее расписание сотрудника не является операторским напоминанием и не изменяется этой процедурой. Напоминание создаёт отдельное исходящее сообщение и не добавляет turn в текущий employee conversation thread, поэтому следующий ответ сотрудника продолжает обычный диалог.

## Три яруса эскалации

1. **Бот → сотрудник.** После preview и подтверждения отправляется одно мягкое напоминание. Сам текст заранее сообщает, что при дальнейшем отсутствии может произойти личное касание методолога и затем передача руководителю только факта участия.
2. **Методолог → сотрудник.** Если касаний по-прежнему нет, методолог связывается лично по согласованному каналу. Он не пересказывает и не интерпретирует содержание corpus.
3. **Методолог → руководитель компании.** При длительном выпадении методолог вправе вручную сообщить только факт участия или отсутствия участия. Machine-access, список разговоров, причины отсутствия, оценки и персональные выводы компании не передаются.

Эскалация не автоматическая: переход между ярусами решает методолог. Метка участия — сигнал для сопровождения программы, а не оценка сотрудника.

## Privacy и протокол оператора

В рабочий протокол входят только дата/время операции, operator identity, company/group scope, метка, digest версии текста, counts и delivery outcomes. Текст переписки, chat ID, Telegram user ID, телефон, trace payload и объяснение причин отсутствия не записываются.

Для проверки процедуры достаточно сохранить preview, факт точного подтверждения и итоговые статусы. Не прикладывать к issue или runbook токены, `.env`, provider payload, invite code или личный диалог.
