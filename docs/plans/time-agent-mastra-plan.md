# План реализации прототипа «Минута» (time-agent) на базе Mastra

## 1. Цель
Простой, надёжный и эффективный прототип (MVP) продукта «Минута»: Telegram-бот с AI-агентом, который помогает сотруднику разбирать и планировать рабочий день, накапливает контекст и генерирует обезличенную «Карту автоматизации» для руководства.

Прототип проверяет три гипотезы:
1. AI-агент способен удерживать контекст сотрудника и давать полезную обратную связь.
2. Персоны («Поддержка» / «Эффективность») заметно влияют на вовлечённость.
3. Из накопленных рефлексий можно автоматически извлечь зоны рутины для автоматизации.

Разработка ведётся ИИ-агентом через подход **Executable Specs** (spec-first цикл).

## 2. Архитектура

### Стек
- **Среда:** Node.js (v20+), TypeScript (`ES2022`, `moduleResolution: "bundler"`).
- **Фреймворк AI:** `@mastra/core` — Agent, Memory, Tools.
- **Интерфейс:** Telegram Bot API (`telegraf`).
- **Хранение:** SQLite (начало) → PostgreSQL (масштабирование). Стандартные адаптеры Mastra Storage.
- **STT:** OpenAI Whisper (подключается на Этапе 3, после проверки текстового ядра).
- **LLM:** Через роутер Mastra (конкретная модель выбирается по результатам теста на качество русского).

### Многопользовательская модель (упрощённая)
Один общий экземпляр `MinutkaAgent`. Изоляция данных пользователей — через встроенные механизмы Mastra Memory:
- `resourceId` = `telegram_user_id` (кто).
- `threadId` = `telegram_chat_id` (контекст диалога).

Персона и профиль пользователя подтягиваются из БД перед каждым вызовом агента и инжектируются в системный промпт динамически. Никакой фабрики агентов не требуется.

### Данные
Данные хранятся в открытом виде в единой базе. Разделение — логическое (по `resourceId`). Вопросы шифрования, KMS и приватности выходят за рамки прототипа.

## 3. Примитивы Mastra

### Agent (`MinutkaAgent`)
Один агент с динамическим системным промптом. Перед каждым вызовом в промпт подставляются:
- Персона пользователя и её тональные правила.
- Профиль: роль, типовые задачи, уровень знакомства с ИИ.
- Жёсткие ограничения из документации: не пишет тексты за сотрудника, не лезет в интернет, не учит ИИ-инструментам (если сотрудник не знаком), отвечает только на темы рабочего времени и связанного с работой эмоционального состояния.

### Tools (2 инструмента)
- **`updateProfileTool`** — сохраняет/обновляет профиль пользователя (роль, задачи, персона, уровень ИИ). Вызывается при онбординге и когда агент замечает новую информацию о пользователе.
- **`extractInsightsTool`** — извлекает из сообщения пользователя структурированные данные: категория задач, паттерны рутины, маркеры энергии/стресса, кандидаты на автоматизацию. Вызывается агентом при утреннем и вечернем разборе.

### Memory
Mastra Memory с привязкой `resourceId` + `threadId`. Агент естественно помнит утренний план при вечернем разборе и учитывает контекст предыдущих дней.

## 4. Ключевые сценарии (из документации → Executable Specs)

### Spec 1: Онбординг и профиль
- **Given** новый пользователь (нет записи в БД).
- **When** отправляет `/start`, отвечает на вопросы агента, выбирает персону «Эффективность».
- **Then** `updateProfileTool` вызывается; профиль сохраняется в БД с корректным `userId`; следующий ответ агента использует тон персоны «Эффективность».

### Spec 2: Утренний план → Вечерняя рефлексия (удержание контекста)
- **Given** пользователь с сохранённым профилем.
- **When** утром отправляет: «Сегодня приоритет — закрыть квартальный отчёт».
- **And** вечером отправляет: «Отчёт не успел, весь день на звонках».
- **Then** агент в ответе ссылается на утренний план; `extractInsightsTool` фиксирует паттерн «звонки» как зону рутины и маркер усталости.

### Spec 3: Ограничение тематики
- **Given** пользователь с профилем.
- **When** отправляет: «Напиши мне пост для соцсети».
- **Then** агент мягко отказывает и возвращает разговор к теме рабочего дня; `extractInsightsTool` НЕ вызывается.

### Spec 4: Обратная связь (👍/👌/👎)
- **Given** агент ответил на вечернюю рефлексию пользователя.
- **When** пользователь нажимает 👎.
- **Then** оценка сохраняется в БД, привязанная к сообщению агента и `userId`.

### Spec 5: Генерация «Карты автоматизации»
- **Given** БД с логами `extractInsightsTool` от ≥5 пользователей за ≥5 дней.
- **When** запускается служебный скрипт агрегации.
- **Then** скрипт выдаёт Markdown-отчёт: топ рутинных задач, зоны стресса, кандидаты на автоматизацию. Без личных имён и данных отдельных сотрудников.

## 5. Этапы реализации (Actionable Steps для AI-агента)

Каждый этап следует циклу: **написать spec → запустить (падает) → реализовать код → spec проходит → коммит**.

### Этап 1: Скелет проекта и тест-харнесс
**Цель:** Рабочий проект Mastra с тестовой средой.
1. Инициализация: `npm create mastra@latest`, настройка TS.
2. Установка: `npm i telegraf dotenv`.
3. Настройка тест-харнесса (`vitest`).
4. Создание заглушки `MinutkaAgent` с hardcoded промптом.
5. **Проверка:** агент отвечает на текстовое сообщение в тесте (без Telegram).

### Этап 2: Онбординг и персоны
**Цель:** Пользователь может пройти онбординг, агент запоминает профиль и меняет тон.
1. Написать и запустить **Spec 1**.
2. Реализовать `updateProfileTool` и динамическую подстановку персоны в системный промпт.
3. Подключить Mastra Memory (SQLite).
4. **Проверка:** Spec 1 проходит.

### Этап 3: Контекст и рефлексия
**Цель:** Агент удерживает контекст дня и извлекает структурированные инсайты.
1. Написать и запустить **Spec 2** и **Spec 3**.
2. Реализовать `extractInsightsTool`.
3. Проверить, что Memory сохраняет контекст между утром и вечером.
4. Проверить, что агент отклоняет нерелевантные запросы (Spec 3).
5. **Проверка:** Spec 2 и Spec 3 проходят.

### Этап 4: Telegram-оболочка
**Цель:** Рабочий Telegram-бот с текстовым вводом.
1. Привязка агента к Telegram-хендлерам (`bot.on('text')`, `bot.command('start')`).
2. Реализация кнопок обратной связи (👍/👌/👎) через inline-клавиатуру Telegram.
3. Написать и проверить **Spec 4**.
4. **Проверка:** ручное end-to-end тестирование в Telegram (текст).

### Этап 5: Голосовые сообщения
**Цель:** Бот принимает голос и транскрибирует.
1. Хендлер `bot.on('voice')`: скачать файл → Whisper API → текст → агент.
2. **Проверка:** голосовое сообщение обрабатывается так же, как текстовое.

### Этап 6: Карта автоматизации
**Цель:** Агрегация инсайтов в обезличенный отчёт.
1. Написать и запустить **Spec 5**.
2. Реализовать служебный скрипт: читает `extractInsightsTool` логи из БД → передаёт LLM → Markdown-отчёт.
3. **Проверка:** Spec 5 проходит на мок-данных 5 пользователей.

### Этап 7 (опционально): Расписание
**Цель:** Автоматические утренние и вечерние пуши.
1. `node-cron` для триггера утреннего / вечернего сообщения.
2. Дневная сверка (midday check-in) — опциональный триггер.
3. **Проверка:** бот инициирует диалог в назначенное время.

## 6. Что за рамками прототипа
- Шифрование данных, KMS, audit log.
- Веб-панель методолога.
- CRM/календарь/задачник интеграции.
- Генерация контента за сотрудника.
- Мобильное приложение.
- Недельные и финальные персональные отчёты (добавляются после валидации ядра).
- B2C-версия.
