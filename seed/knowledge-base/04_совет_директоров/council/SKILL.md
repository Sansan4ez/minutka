# Skill: Совет директоров

Универсальный навык. Автоматически адаптируется под проект и тип задачи. Главная ценность — **конфликт мнений** между голосами, не количество ролей.

## Когда использовать

- Разбор текстов: рассылки, retention, лендинги, оферты, питчи
- Проверка маркетинговой логики: воронки, скидки, цепочки касаний
- Аудит существующей системы работы с клиентом
- Оценка продуктовых гипотез
- Поиск пропущенных возможностей

## Когда НЕ использовать

- Технические задачи (есть `/perf-review`, `/proxy-defense`, `/handoff`)
- Простые правки текста («поправь слово»)
- Когда решение уже принято — нужно просто внедрить

## Порядок действий

### Шаг 1. Понять задачу (всегда)

Если `/council` вызван без аргументов или с туманной формулировкой — **сначала спросить**:
1. Что разбираем? (текст / гипотеза / воронка / лендинг / другое)
2. Какая цель? (повышаем конверсию / снимаем возражение / меняем восприятие бренда / другое)
3. Как поймём, что разбор сработал? (метрика и срок)

Если бизнес-смысла нет — **отказаться от разбора** и предложить сначала сформулировать цель. Это правило CSO.

### Шаг 2. Авто-адаптация под проект

Прежде чем собирать совет:
1. Прочитать `CLAUDE.md` проекта (если есть) — что за продукт, аудитория, специфика
2. Прочитать память: ищи файлы `feedback_*`, `project_*` — там могут быть правила tone of voice, прошлые решения, ограничения
3. **Извлечь аватаров ЦА из контекста проекта**, не из шаблона. 3-5 типичных пользователей с конкретным «зачем им продукт». Шаблонные аватары («обходчик», «студент») — только если они реально подходят, иначе строить своих.

Если контекста нет — спросить у пользователя «опиши ЦА в 1-2 предложениях».

### Шаг 3. Подобрать состав совета под тип задачи

Не все голоса нужны всегда. Минимум — 2-3 со встроенным конфликтом.

| Тип задачи | Обязательно | Опционально |
|---|---|---|
| Retention-текст / рассылка | CMO + CSO + 2-3 аватара | Джобс (если про камерность) |
| Аудит системы / стратегия | CMO + CSO + Маск + Безос | Джобс, Котлер |
| Новый продукт / гипотеза | Маск + Джобс + 1-2 аватара | Котлер |
| Лендинг / питч | CMO + CSO + 1 аватар-целевой | Джобс |
| Кризис-коммуникация | CMO + Безос | Джобс |
| Сегментация / методология | Котлер + CSO + CMO | — |
| Заголовки / оферта / рекламный текст | CMO + Огилви + 1 аватар | CSO |
| Сообщество / виральность / ребрендинг | CMO + Сет Годин + Маск | Безос |
| Долгосрочные решения / финансовая устойчивость | Бафетт + CSO + Котлер | Безос |
| Масштабирование / культура / найм | Коллинз + Безос + CMO | Друкер |
| **Миссия / приоритеты / «зачем существуем»** | **Друкер + Коллинз + Котлер** | Безос |

**Расширенный состав** (Маск/Джобс/Безос/Котлер) — по запросу пользователя «расширенный совет» или когда задача стратегическая.

### Шаг 4. Прогон через совет

**Каждый голос реагирует от первого лица** — живая речь, не сухая критика. Цитаты в стиле роли.

**Обязательно искать разногласия.** Если все голоса согласны — это сигнал поверхностного разбора, отметить явно: «единогласие — возможно, упустили что-то, разберём глубже» и копнуть.

**Голоса (краткие профили):**
- **🎨 CMO** — бренд, эмоции, нейромаркетинг, tone of voice
- **💰 CSO** — конверсия, экономика оффера, возражения, метрики
- **🚀 Илон Маск** — оспаривает сам процесс, ищет локальные максимумы, поведенческие сигналы > календарные. First Principles Thinking
- **🍎 Стив Джобс** — «уберите 50% того, что вы написали», камерность, смысл, не корпоративность
- **📦 Джефф Безос** — мыслит от клиента назад, проактивная забота, снятие риска, сбор боли вместо хвалы
- **📊 Филип Котлер** — методология, relationship vs transactional, сегментация по смыслу
- **💎 Уоррен Бафетт** — долгосрочность, осторожность, реальная ценность vs хайп. Звать для решений с горизонтом 5-10 лет, оценки устойчивости модели
- **📝 Дэвид Огилви** — мастер копирайтинга. Заголовок = 80% успеха, факты сильнее эпитетов. Звать для заголовков, оферт, рекламных текстов
- **🟣 Сет Годин** — племя, разрешительный маркетинг, «фиолетовая корова», виральность через идентичность. Звать для сообщества, виральных механик, ребрендинга
- **🦔 Джим Коллинз** — Good to Great, ёж-концепция, дисциплина масштабирования. Звать для перехода от роста к удержанию качества, найма, культуры
- **🧭 Питер Друкер** — отец менеджмента. «Делать правильные вещи» vs «делать вещи правильно». Звать ТОЛЬКО для миссии/приоритетов/«зачем существуем», не для тактики
- **🧱 Аватары ЦА** — извлечены из контекста проекта

### Шаг 5. Финальное совещание

Сводим разногласия в решение. **Явно назвать конфликты и как они разрешены.**

Если есть фундаментальное разногласие, которое нельзя разрешить без владельца — вынести как вопрос владельцу, не угадывать.

### Шаг 6. Формат вывода — под задачу

| Тип | Финал |
|---|---|
| Retention-текст | Полный текст с переменными `{placeholder}` + кнопки + что изменилось vs оригинал |
| Гипотеза | Рекомендация: внедрять / нет / переформулировать. С обоснованием от 2-3 голосов |
| Лендинг | Структура: блоки, последовательность, что в каждом блоке |
| Аудит системы | Топ-10 правок по приоритету + вопросы владельцу |
| Стратегия | 3-5 направлений с обоснованием конфликта/единогласия |

**НЕ навязывать «нейромаркетинговый апгрейд», «3 приёма с примерами», «таблицу сводки» если задача их не требует.** Это инструменты у голосов, не пункты ритуала.

### Шаг 7. Журнал решений

После каждого запуска — дописать **ОДНУ строку** в `docs/.council-log.md` (создать если нет):
```
- 2026-05-15 | retention 26 триггеров | убрали 50% на день 5, разнесли скидку/отзыв | проверить через месяц по конверсии триал→платный
```

Это пишется коротко, не отдельный документ. Через 10 запусков владелец видит паттерны.

## Режимы

- `/council` — спросит что разбирать
- `/council <описание>` — full режим, полный состав по типу задачи
- `/council fast <текст или вопрос>` — 2-3 голоса, минимум структуры, быстрый ответ
- `/council расширенный <описание>` — Маск/Джобс/Безос/Котлер обязательно

## Правила голосов

1. Реакция **от первого лица**, со своим стилем — не «холодная критика»
2. **Конкретика > общие слова** — не «текст плохой», а «слово X создаёт эффект Y»
3. **Не выдумывать факты** про продукт — спросить или прочитать из БД/кода
4. **Не предлагать менять продукт** (новые тарифы, фичи) — только тексты, логику, позиционирование
5. Если в проекте есть `feedback_*` файлы в памяти — следовать им (там зафиксированные правила tone of voice)

## Универсальный стоп-лист (применяется всегда)

- ❌ Манипуляции страхом / виной
- ❌ Агрессивное FOMO («ТОЛЬКО СЕГОДНЯ!!!», капс)
- ❌ Превосходство («все ваши друзья уже»)
- ❌ Корпоративный канцелярит («уважаемый клиент», «уведомляем»)
- ❌ Слащавость и фейк («без вас мы бы не существовали»)
- ❌ Выдумывать цены/политики/факты продукта

## Артефакт

Результат сохранять в файл проекта (не править существующие планы). Имя файла — спросить или предложить:
- `docs/.../COUNCIL_REVIEW_{topic}.md` для крупного разбора
- встроенный ответ в чате — для fast-режима

Если задача — обновить существующий план, делать это **отдельным шагом после одобрения владельца**, не автоматически.

## Объяснения терминов

Если используются термины (якорение, peak-end, IKEA-эффект, social proof) — давать **краткое пояснение в скобках** для не-маркетолога. Не сыпать жаргоном.

## Инструментарий совета (фреймворки и приёмы)

Голоса оперируют известными моделями. **Правила применения:**

1. **1-2 фреймворка на разбор максимум** — больше = шум
2. **Применять только если меняет вывод.** Если без фреймворка ответ был бы тем же — не тащить ради красоты
3. **Называть вслух:** «применяю JTBD: ...» с **одной строкой пояснения** для не-маркетолога
4. **Не путать фреймворки и приёмы.** Приёмы (якорение, peak-end) — это рычаги, фреймворки (AIDA, SPIN) — это структуры. Приёмов в одном тексте может быть несколько, фреймворк — обычно один ведущий.

### Базовый набор (20+ моделей, актуальные для 2026)

**Маркетинг и копирайтинг (обычно использует CMO):**
- **AIDA** (Attention/Interest/Desire/Action) — универсальная воронка текста
- **PAS** (Problem/Agitate/Solution) — тексты через боль
- **4U** (Urgency/Usefulness/Uniqueness/Ultra-specificity) — заголовки и оферты
- **Before-After-Bridge** — текущее → желаемое → мост
- **FAB** (Features/Advantages/Benefits) — продуктовые описания
- **Star-Story-Solution** — герой → история → решение, для сторителлинга

**Стратегия и позиционирование (CMO/Котлер):**
- **STP** (Segmentation/Targeting/Positioning) — кому и как продаём
- **JTBD** (Jobs To Be Done) — какую «работу» клиент нанимает продукт сделать
- **Buyer Persona** — портреты ЦА
- **Brand Pyramid** — атрибуты → выгоды → ценности → лояльность
- **Customer Journey Map** — путь клиента по точкам касания

**Продажи (CSO):**
- **SPIN** (Situation/Problem/Implication/Need-Payoff) — вопросы для выявления потребности
- **BANT** (Budget/Authority/Need/Timing) — квалификация лида
- **MEDDIC** — сложные B2B-продажи
- **Feel-Felt-Found** — работа с возражениями
- **Solution Selling** — продажа решения, не продукта

**Поведенческие и продуктовые (Маск/Безос):**
- **AARRR** (Acquisition/Activation/Retention/Referral/Revenue) — продуктовая воронка
- **The Hook Model** (Trigger/Action/Reward/Investment) — формирование привычек
- **Kano Model** — базовые/производные/восхищающие функции

**Бизнес и операции (Безос/Котлер):**
- **SWOT** — сильные/слабые/возможности/угрозы
- **5 сил Портера** — конкурентное поле
- **PEST** — макрофакторы (политика/экономика/соц/тех)
- **OKR** — цели и ключевые результаты
- **PDCA** (Plan/Do/Check/Act) — цикл улучшений

**Психология и убеждение (все голоса):**
- **6 принципов Чалдини** — взаимность / обязательство / социальное доказательство / симпатия / авторитет / дефицит. Фундамент убеждения, применим везде
- **First Principles Thinking** (метод Маска) — разложить задачу до базовых истин, отбросить аналогии. Звать когда «все делают X» и непонятно почему

**Стартапы и продукт (Маск/Безос):**
- **Lean Canvas** (Maurya) — упрощённый BMC под гипотезы и MVP. 9 блоков на одну страницу
- **Customer Development** (Steve Blank) — выход к клиенту вместо догадок в кабинете. «Get out of the building»
- **Unit Economics** (CAC, LTV, Payback) — экономика клиента. Без этого нельзя обсуждать офферы и retention

**Бренд и архетипы (CMO/Сет Годин):**
- **12 архетипов бренда** (Jung/Pearson) — Герой / Маг / Бунтарь / Мудрец / Невинный / Исследователь / Любовник / Шут / Хранитель / Правитель / Творец / Простой парень. Каждый бренд = доминирующий архетип

### Нейромаркетинговые приёмы (рычаги, не фреймворки)

Это инструменты «у CMO в голове». Применяются точечно внутри текста, обычно несколько вместе:

- **Якорение** — зачёркнутая цена / точка отсчёта. Мозг считает экономию от якоря
- **Loss aversion** — страх потерять > радость приобрести (мягко, без манипуляции)
- **Peak-end** — впечатление формируется по пику эмоций и финалу, не по среднему
- **Reciprocity** — отдал → создал обязательство ответить
- **IKEA-эффект** — клиент ценит то, во что вложил усилия (даже маленькие)
- **Social proof** — «другие выбрали это» — только реальное, без выдумок
- **Endowment effect** — то, что уже «в руках» клиента, ценится выше
- **Zeigarnik-эффект** — незавершённое запоминается лучше завершённого
